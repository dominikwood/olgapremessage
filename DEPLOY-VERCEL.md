# Публикация на Vercel

Подготовлено для домена **olgraprem.org.ua**, в точности как он указан в задаче. Это не `olgaprem.org.ua`: проверьте написание перед настройкой DNS. В рамках этой подготовки сайт не публиковался; аккаунт Vercel, GitHub и записи DNS не изменялись.

## 1. Что уже подготовлено

Страница, изображения, шрифты и MP4 раздаются из `public` через CDN Vercel. Форма вызывает `/api/apply`, отдельную Node.js Function. Видеофайлы не проходят через функцию Telegram. Локальный сервер использует тот же обработчик заявок.

Нет платных библиотек и внешних зависимостей приложения. Используется Node.js 24.x. Добавлены проверка сборки, автоматические серверные тесты, исключения секретов/QA, canonical, robots.txt и sitemap.xml. Дизайн и порядок секций не менялись.

Для коммерческого сайта с продажей курса выбирайте **Pro** либо Enterprise: Hobby ограничен некоммерческим личным использованием. Покупка тарифа не выполнена. [Правила Vercel](https://vercel.com/docs/limits/fair-use-guidelines).

## 2. Подготовьте Telegram

Нужны два серверных значения:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Секретный токен бота, которым вы владеете; получите у официального @BotFather или администратора своей интеграции. |
| `TELEGRAM_CHAT_ID` | ID приватного чата или закрытой рабочей группы, куда должны поступать заявки. Это не `@aromaprem_bot` и не номер телефона. |

Для приватного чата сначала откройте своего бота и нажмите Start / отправьте `/start`, иначе бот не сможет первым написать пользователю. Для закрытой группы добавьте бота и проверьте право отправлять сообщения. Не направляйте контактные данные посетителей в публичный канал.

Если chat ID уже есть в настройках вашего бота, используйте его. Если нет, можно локально выполнить:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# В .env укажите TELEGRAM_BOT_TOKEN, не публикуя его.
node --env-file=.env scripts/telegram-chat-id.js
```

Перед командой отправьте боту новое сообщение. Скрипт выводит только ID/тип найденных чатов, не токен и не тексты переписки. Он не отправляет сообщения и не меняет webhook. Если бот уже управляется другим сервисом через webhook/polling, не нарушайте его работу: возьмите chat.id из той интеграции. Этот вспомогательный скрипт в ходе подготовки проекта не обращался к вашему боту.

Запишите выбранный ID в локальный `.env` для разработки. Сам `.env` не загружайте в GitHub или Vercel; в облаке значения вводятся отдельно. [Руководство Telegram](https://core.telegram.org/bots/tutorial).

## 3. Проверка на компьютере

В PowerShell из папки проекта:

```powershell
Set-Location 'F:\Оля Прожекторы\Оля Массаж Сайт'
node --version
npm ci
npm test
npm run build
npm start
```

Версия Node должна быть 24.x. Адрес локального сайта: http://localhost:3000. Если порт занят вашим уже запущенным сайтом, используйте его или задайте другой `PORT` для локальной разработки. В Vercel `PORT` не добавляйте.

`npm test` не отправляет настоящие заявки. `npm run build` проверяет существование файлов с точным регистром, синтаксис и основные условия деплоя. В Production-сборке Vercel он дополнительно требует обе переменные Telegram. Папка `public` уже содержит готовую страницу: отдельная генерация HTML не нужна.

## 4. Вариант A: GitHub и интерфейс Vercel

Рекомендуется для дальнейших обновлений сайта.

1. Создайте пустой приватный репозиторий в своём GitHub, например `olga-prem-site`. Не создавайте в нём отдельные README/.gitignore до первой загрузки локального проекта.
2. Загрузите **корень проекта**, включая папки `public`, `api`, `lib`, `scripts`, `tests`, а также `package.json`, `package-lock.json`, `vercel.json`, `server.js`, `.gitignore`, `.vercelignore` и инструкции. Не загружайте `.env`, логи, `qa`, `.codex-*`, `node_modules` или `.vercel`. Для Git загрузку ограничивает `.gitignore`.
3. Через Git это можно сделать так, заменив пример адреса на настоящий URL своего пустого репозитория:

```powershell
git init -b main
git add .
git status --short
# Убедитесь, что .env и другие секреты отсутствуют в списке.
git commit -m "Prepare Olga Prem site for Vercel"
git remote add origin https://github.com/YOUR_ACCOUNT/olga-prem-site.git
git push -u origin main
```

4. В Vercel выберите **Add New → Project**, подключите GitHub и импортируйте этот репозиторий в подходящую коммерческую команду/тариф.
5. Проверьте настройки перед Deploy:

| Поле | Значение |
| --- | --- |
| Framework Preset | Other |
| Root Directory | Корень репозитория, не `public` |
| Node.js Version | 24.x |
| Build Command | `npm run build` |
| Output Directory | `public` |
| Install Command | `npm ci` |

Эти настройки уже зафиксированы в `vercel.json` и `package.json`, кроме выбора аккаунта/тарифа. Не выбирайте Express или Next.js и не ставьте `npm start` в Build Command. [Конфигурация Vercel](https://vercel.com/docs/project-configuration/vercel-json).

6. До первого Production Deploy добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в **Environment Variables**, область **Production**. Используйте серверные переменные без префиксов `NEXT_PUBLIC_`/`VITE_`. Если интерфейс помечает секретные значения как Sensitive, используйте эту возможность. Не вставляйте токен в исходные файлы.
7. Нажмите **Deploy**. При успехе появится временный адрес `*.vercel.app`. Проверьте его до подключения домена.
8. Для веточных Preview используйте отдельного тестового бота/чат либо не задавайте там Telegram-переменные: тогда сам сайт доступен, но отправка формы вернёт ошибку до настройки. Не копируйте автоматически реальные заявки в тестовые окружения.

После добавления или изменения переменных выполните **Redeploy**: они применяются к новым деплоям, а не к уже работающему. [Переменные окружения](https://vercel.com/docs/environment-variables).

## 5. Вариант B: без GitHub, через Vercel CLI

Вместо раздела 4 можно отправить текущую папку напрямую. Команды ниже выполняйте самостоятельно: они связывают проект с вашим аккаунтом и публикуют сайт.

```powershell
npx vercel login
npx vercel link
npx vercel env add TELEGRAM_BOT_TOKEN production
npx vercel env add TELEGRAM_CHAT_ID production
npx vercel --prod
```

Вводите значения в интерактивных запросах CLI, не пишите токен аргументом команды. При link выберите нужную команду/аккаунт и создайте новый проект либо выберите свой существующий. Корень — текущая папка. Настройки сборки берутся из `vercel.json`. Секреты и QA исключены из CLI-загрузки по allowlist в `.vercelignore`.

Этот способ не включает автоматический деплой из GitHub: после следующих правок нужно снова выполнить `npx vercel --prod`.

## 6. Подключите olgraprem.org.ua

1. В опубликованном проекте Vercel откройте **Settings → Domains → Add Domain** и добавьте `olgraprem.org.ua`.
2. При необходимости добавьте `www.olgraprem.org.ua` и настройте в Vercel его постоянный редирект на основной домен без `www`.
3. Откройте управление DNS у текущего DNS-провайдера/регистратора. Для корня зоны обычно нужна запись **A** с именем `@`, для `www` — **CNAME**. **Точные значения скопируйте из Vercel для вашего домена**, не из старых инструкций и не по памяти. Провайдер может ожидать полное имя вместо `@`.
4. Удалите/измените только конфликтующие веб-записи для этого же имени, например старый A/AAAA или CNAME. **Не удаляйте MX, SPF, DKIM, DMARC и записи других сервисов.** Смена NS не обязательна; если её всё же делаете, заранее перенесите нужные DNS-записи.
5. Если Vercel запросит TXT для подтверждения владения, добавьте именно выданную запись. Домен не нужно переносить к другому регистратору.
6. Дождитесь статуса **Valid Configuration** и выпуска HTTPS-сертификата. Затем проверьте `https://olgraprem.org.ua/` и редирект с `www`, если он подключён. Время обновления зависит от DNS и TTL.

Записи DNS намеренно не внесены в проект как выдуманный IP/CNAME: Vercel показывает актуальные значения для конкретного подключения. [Официальная инструкция по домену](https://vercel.com/docs/domains/working-with-domains/add-a-domain).

Canonical, Open Graph URL, sitemap и robots уже указывают на `https://olgraprem.org.ua/`. Если написание домена изменится, обновите `public/index.html`, `public/robots.txt`, `public/sitemap.xml` и домен в проверке ссылок `scripts/check-deploy.js`.

## 7. Защита и расходы

- В Vercel Firewall настройте для POST `/api/apply` rate limit по IP. Для начала можно рассмотреть 5 запросов в минуту с последующей корректировкой по реальной статистике. Действие должно ограничивать запросы, а не только писать Log. Это предложенная настройка, не автоматически включённое правило. [Настройка rate limiting](https://vercel.com/kb/guide/add-rate-limiting-vercel).
- В коде уже есть honeypot, проверка Origin браузерных запросов, JSON-only, лимит тела 10 000 байт, проверка полей, отсутствие токена в ответах и тайм-аут Telegram 8 секунд. Это не CAPTCHA и не полноценная распределённая защита от ботов. Без состояния rate limit не хранится в памяти функции: разные экземпляры Vercel не разделяют такую память.
- Настройте бюджет/уведомления расходов в своём аккаунте Vercel, следите за трафиком MP4. Все публичные файлы сейчас занимают около 40 MiB, два видео — около 20 MiB суммарно. Видео можно оставить на Vercel; при росте просмотров имеет смысл отдельно оценить медиахостинг. Медиа не перекодировались и не переносились.
- Используйте приватный репозиторий. Если токен когда-либо попал в Git/публичный доступ, перевыпустите его у BotFather: одного удаления строки недостаточно.
- Сервер не записывает заявки в отдельную базу и не логирует их содержимое. Это не исключает хранение в Telegram, инфраструктурные логи Vercel или копии у получателей.

## 8. Финальная проверка после публикации

1. Откройте сайт по HTTPS на телефоне и компьютере, переключите UA/RU. Отложенные правки иконок и оформления текста в эту подготовку не входили: при ширине 390 px длинный русский заголовок и CTA первого экрана всё ещё выходят за видимую ширину. Это сохранённое поведение текущего дизайна, не исправленное в рамках настройки хостинга.
2. Проверьте изображения, обе карусели, увеличение отзывов, оба видео: запуск только по нажатию и перемотка.
3. Отправьте **одну осознанную тестовую заявку** из каждого нужного окружения и убедитесь, что она пришла в правильный приватный чат с нужным пакетом. Наши автоматические тесты Telegram имитируют, поэтому реальная доставка ещё не подтверждена.
4. Проверьте, что форма снова доступна после успеха и ошибки. Открытие `/api/apply` в адресной строке должно давать 405, а не страницу с секретами: этот адрес принимает только POST.
5. Проверьте `/robots.txt`, `/sitemap.xml`, canonical и `/index.html` → `/`.
6. Убедитесь, что `.env`, README, тесты и внутренние документы не доступны как статические страницы. `public` — единственная статическая корневая папка.
7. Посмотрите Vercel Functions/Runtime Logs без публикации токенов и персональных данных. В текущей версии ответы 503 обычно означают отсутствие настроек Telegram; 502 — ошибку доставки, 504 — тайм-аут. Не считайте сообщение формы подтверждением доставки, пока не увидели его в правильном чате.
8. Юридические документы ранее отменены и не возвращены. До открытого приёма заявок/продаж отдельно завершите согласование необходимых юридических сведений и правил обработки данных. Техническая подготовка этого не заменяет.

## 9. Следующие обновления и откат

При GitHub-варианте после локальных проверок сделайте commit/push в Production Branch (обычно `main`): Vercel создаст новый деплой. Перед обновлением существующих файлов медиа учитывайте браузерный кэш до часа; для мгновенной смены используйте новое имя файла/URL. Для JavaScript уже используются версии в URL.

При проблеме откройте **Deployments** и выполните откат на предыдущий успешный Production deployment. DNS для обычного обновления дизайна менять не нужно.

Актуальность проверенных инструкций: 15 октября 2026. Фактический импорт в аккаунт Vercel, Production-сборка на платформе, DNS/HTTPS и настоящая Telegram-доставка проверяются после публикации владельцем.
